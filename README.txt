Лабораторна робота 5. Програмний додаток над базою даних «Готель» (варіант 1)
=============================================================================

Веб-додаток для адміністратора готелю: Python 3, Bottle, SQLAlchemy (ORM),
PostgreSQL, uWSGI, nginx, memcached. База даних, тригери, процедури й кеш
взяті з лабораторної роботи 4 без змін (папка postgres).


Що всередині
------------
app/                  веб-додаток
  lab5.py             маршрути Bottle, шаблони викликаються звідси
  hotel/models/       ORM-моделі таблиць
  hotel/validation.py перевірка й нормалізація введених даних
  hotel/services.py   операції зі змінами даних: кожна в одній транзакції
  hotel/queries.py    чотири запити з варіанта (ORM)
  hotel/db.py         підключення, транзакції, збір повідомлень бази
  hotel/seed.py       додаткові тестові дані
  views/, static/     сторінки (SimpleTemplate) і стилі
  tests/smoke_test.py наскрізна перевірка через HTTP
nginx/                конфігурація nginx (додаток на :8088, REST-кеш на :8089)
postgres/init/        SQL-скрипти створення бази (виконуються при першому старті)
postgres/scripts/     демонстраційні скрипти лабораторної роботи 4
docker-compose.yml    сервіси: memcached, postgres_db, app, adminer, nginx
compose.bat, bash.bat допоміжні команди для Windows


Запуск у Docker
---------------
Потрібен запущений Docker Desktop.

  compose.bat                       (зупиняє, видаляє старі контейнери й томи,
                                     збирає образи й запускає все наново)
  docker ps                         (мають працювати п'ять контейнерів)

Для запуску без Windows-скрипта:

  docker-compose -p lab5 up -d --build

Першого разу база створюється з postgres/init. Щоб почати з чистої бази,
зупиніть контейнери й видаліть папку postgres\data.

Адреси:
  http://localhost:8088                  веб-додаток
  http://localhost:8089/availability     кеш: вільні номери й місця (JSON)
  http://localhost:8080                  Adminer (сервер postgres_db, користувач
                                         root, пароль password, база hotel)
  localhost:8432                         PostgreSQL для DBeaver (root / password)


Додаткові тестові дані
----------------------
Початкових даних лабораторної 4 замало для демонстрації (7 клієнтів), тому є
скрипт, який додає ще 11 клієнтів, 12 проживань та 3 службовців із графіком.
Він використовує ті самі процедури check_in, check_out, hire_employee,
change_schedule. Повторний запуск нічого не дублює.

  docker exec -it lab5-app-1 python -m hotel.seed

Увага: скрипти лабораторної 4 (postgres/scripts) розраховані на початкові
дані. Номери 101, 102, 201, 203, 401 і паспорти, які вони використовують,
скрипт додаткових даних не чіпає, але загальні підрахунки (кількість клієнтів,
вільних місць) після нього будуть іншими.


Перевірка роботи додатку
------------------------
Наскрізний тест проходить основні сценарії через HTTP (49 перевірок). Додаток
і база мають працювати. Із папки app на комп'ютері (потрібен Python 3):

  cd app
  set APP_URL=http://localhost:8088
  python tests/smoke_test.py

Тест сам прибирає створені записи, тому його можна запускати повторно.


Запуск без Docker (для розробки)
--------------------------------
Контейнери postgres_db і memcached мають працювати (docker-compose up -d
postgres_db memcached). Далі:

  cd app
  pip install -r requirements.txt
  set DATABASE_URL=postgresql+psycopg2://root:password@localhost:8432/hotel
  python lab5.py

Додаток відкриється на http://localhost:8085 (порт можна змінити змінною PORT).
Змінна SQL_ECHO=1 виводить у консоль усі SQL-запити.


Основні правила, які діють у додатку
------------------------------------
- Правила цілісності (місткість, перетин проживань, поверхи тощо) і оновлення
  кешу виконує база даних: тригери з лабораторної 4. Додаток їх не дублює, а
  перетворює помилки бази на зрозумілі повідомлення.
- Кожна зміна даних виконується в одній транзакції: або вдається повністю,
  або не змінюється нічого (наприклад, при невдалому заселенні новий клієнт
  теж не зберігається).
- Дані з форм перевіряються й нормалізуються до звернення до бази (паспорт,
  імена, місто, телефон, дати, ціна, місткість, номер кімнати й поверх).
- Якщо memcached недоступний, зміни даних усе одно зберігаються, а на екрані
  з'являється попередження про кеш.
